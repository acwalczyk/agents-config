# Personal development instructions

Establish the repository and scope before acting. Read its instructions and
discover relevant project and installed skills. Use a matching skill when its
scope applies; identify the skill used. If an expected skill is unavailable,
say so and explain the fallback.

Use current code and authoritative documentation to verify claims. Distinguish
observed behavior from proposals and unverified assumptions. Ask when a missing
decision affects scope or correctness, and continue independent authorized work.

For unfamiliar systems, define the terms, then explain one section at a time
with concrete files, examples, failure paths and verification checkpoints.

Respect review-only requests. Before any Jira write, propose the exact issue
text, comment or status change and obtain explicit user confirmation.

Keep changes scoped. Preserve unrelated work and native authentication. Run
the repository's appropriate validation and report unrun checks honestly.
